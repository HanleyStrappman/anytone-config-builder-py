Anytone Config Builder

Builds the channel, zone, scanlist and talkgroup files the Anytone CPS imports, from four readable CSV files you can keep under version control. Pick your files, choose a CPS format, and get back a zip of the lot.

The DMR and analog files are available on the PNWDigital.net site. You will need to generate the airband files yourself.

Everything runs in your browser. Your files are never uploaded — there is no server here to upload them to.

Your files

Analog FM channels. Zone, Channel Name, Bandwidth, Power, RX Freq, TX Freq, CTCSS Decode, CTCSS Encode, TX Prohibit

One-off DMR channels — simplex, hotspots, digital APRS.

The repeater × talkgroup matrix, multiplied out into one channel per repeater per talkgroup. Where most of the work happens.

Two columns, no header: talkgroup name and numeric ID. Names must match the ones the two DMR files above use.

Only CPS format 3 reads the result. Leave this empty and the radio keeps whatever airband channels it already has.

Options

Which layout your CPS wants is a property of the CPS, not of the radio — a newer CPS for the same radio can read a different one. Format 1 is the default because it is what the original Perl tool wrote. If you are unsure, export a codeplug from your own CPS and compare its column headers against the files you get back. Formats 1 and 2 differ from column 11 onward, so the wrong choice can import without complaint and put every value in the wrong field.

My CPS is not in the list

A CPS format is a file, not something built into this page. The quickest start is the shipped format nearest your CPS: save its files, change the headings and defaults to match a codeplug exported from your CPS, rename both to a name of your own, and pick them here. They join the list above.

    channel-defaults-name.csv — required, and usually the whole format

    One row per column of your CPS's channel export, holding the column number, the heading your CPS gives it, and the value to use when the input CSVs do not say:

    0,No.,REQUIRED
1,Channel Name,REQUIRED
...
20,RX Color Code,0
21,Slot,1
22,Scan List,REQUIRED

    REQUIRED marks a column the inputs must fill; a build that reaches one still empty stops and says which. Whatever stands where name is becomes the format's name in the list. Which of the builder's fields lands in which column is worked out from the headings, so a CPS that uses the names Anytone has used so far needs nothing else.

    format-name.csv — optional, beside it

    For what a channel layout cannot say: what the zone, scanlist and talkgroup files are called, and the handful of places their shape differs. Without it, everything defaults to what formats 2, 3 and 4 all do, which is what a newer CPS is most likely to want. A key and a value per row; rows beginning with # are comments.

    KeyDefault
    labelthe format name What the list above calls it.
    testedno Whether it has been checked against a real CPS export.
    freq_decimals5 Decimal places for frequencies, or as-is to pass the input through.
    zone_hideyes The trailing Zone Hide column on zones.
    talkgroup_notesno Country and Remarks columns on talkgroups.
    member_freqsyes RX/TX frequency columns beside each channel name in zones and scanlists.
    airbandno Whether this CPS reads the AMAir.CSV / AMZone.CSV pair.
    file.channels etc. channels.csv etc. What this CPS calls each of the four outputs: file.channels, file.zones, file.scanlists, file.talkgroups.
    column.nderived Force column n, for a heading the builder does not recognise. Empty unmaps it.

    A key that is not one of these is an error rather than something skipped: a misspelled zone_hide that quietly did nothing would produce a codeplug the CPS imports without complaint and fills in wrong. Unless a format says tested,yes, building on it warns that it has not been checked against a real CPS export. Nothing stops you; compare what comes back against a codeplug exported from your own CPS before trusting it.

    Pick the files

    Nothing is kept. The file lives in this tab and goes when you close it, so keep your copy wherever you keep your other codeplug CSVs and pick it again next time.

    alpha sorts every zone by name. The other two put the repeater zones before or after the analog and digital-other ones.

    Works a zone's nickname into each channel name: ARA Audio Test 2 rather than Audio Test 2. With off, every repeater's channels are named after nothing but their talkgroup, so thousands of channels collapse onto a hundred-odd names the radio cannot tell apart.

    always sets TX Permit to Always on channels whose RX and TX frequencies match, which is what a hotspot wants.

    Starting…

    Before importing into the CPS

    • Duplicate names. Repeater channels are named after their talkgroups, so the same name recurs across repeaters. Turn on Tools > Mode > “Contact name is not unique / Channel name is not unique” first, or the import will fail.
    • Radio ID. The output references a radio ID named DMR ID. Under the Digital tab, add your DMR ID to the Radio ID List under that name.
    • Contacts. Not generated. Start from a codeplug that has them, then import these files over the top.
